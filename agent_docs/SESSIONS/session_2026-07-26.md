## Lessons Learned
1. **`agent_docs/RESPONSES/` is not optional and is not the same as the session file.** The session file tracks *status transitions*; RESPONSES holds the *full artifact*. Both writes fire on every plan/report. Missed all three this session.
2. **A skill's own output contract does not satisfy the global protocol.** The recon went to `agent_docs/RECON/` per `stark-recon`'s contract — correct, but it still owed a `RESPONSES/` entry. Skill contract and global protocol stack; they don't substitute.
3. **Doctrine files drift like any other doc.** The recon's whole premise ("docs lie, disk wins") applied to `CLAUDE.md` itself — line 510 was the direct cause of a real misfile. Worth grepping doctrine against actual repo layout periodically.
4. **When a fix has two copies of one artifact, delete the copy — don't sync it.** `docs/setup.sql` vs `supabase/setup.sql` drifted precisely because Gate 10 had to remember to update both. It didn't.
5. **🔴 A summary count from `npm audit` is not an inventory.** The recon reported "4 high = sharp" because I grepped the audit output for the package I already suspected. Fixing sharp revealed 4 *different* high advisories that the same count had been hiding — including a production `next` advisory (unauthenticated disclosure of internal Server Function endpoints). **Recon must capture `npm audit --json` metadata + the full package list, never a grep for the suspected name.** Candidate addition to `stark-recon`'s `RECON_MISSION.md` Section 6.
6. **Test dependency changes in an isolated lockfile copy before proposing them.** `cp package.json package-lock.json` to scratch → `npm install --package-lock-only` → `npm audit` proves a remedy reaches zero without touching the repo. It also caught the `EOVERRIDE` rule (an override cannot conflict with its own direct dependency) that would otherwise have blown up mid-apply.
